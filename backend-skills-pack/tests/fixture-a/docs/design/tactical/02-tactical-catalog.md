# 02 Tactical design: Catalog

## Inputs
- docs/design/project-profile.md: TypeScript with NestJS; PostgreSQL; REST; modular monolith, one module per context; in-process domain events plus a transactional outbox per module, drained by a background worker; UUIDv7 ids generated by the application; RFC 9457 errors with a "code" member.
- docs/design/01-strategic.md: Catalog row (owns REQ-1, REQ-2, REQ-3, REQ-4, REQ-24), D1-2, D1-3, D1-10, context map rows Catalog -> Lending (BookAdded) and Lending -> Catalog (BookAvailabilityChanged), separate-ways row with Fines, open host service row Membership -> Catalog (ResolveCurrentMember), Published language of all four contexts, Ubiquitous language (Book, Availability, Search, ISBN in Catalog).
- docs/design/00-project-brief.md: rows REQ-1, REQ-2, REQ-3, REQ-4, REQ-24, REQ-29 and Actors (Visitor, Member, Librarian).
- Rulebook: .claude/skills/backend-design-team/references/default-rulebook.md. No project rules file (profile).

## Decisions
- D2-1 One aggregate, Book, holding the bibliographic record (title, author, ISBN). Why: the only invariants Catalog owns are about one record (REQ-24); copies belong to Lending (D1-2). Proposed.
- D2-2 Title, author and ISBN are value objects on Book, replaced as a whole, never edited in place. Why: no identity of their own (TAC-08). Proposed.
- D2-3 ISBN uniqueness across books is a set rule over many Book instances. It is enforced by a unique constraint on the normalised ISBN, checked in the same transaction that inserts the Book in AddBook, not by a second aggregate. It applies only if Q-10 / CQ-1 confirm uniqueness. Proposed.
- D2-4 Availability is the read model BookAvailability, built only from the Lending integration event BookAvailabilityChanged (D1-3). Catalog never computes availability from copies and it holds no invariant. Source of truth is Lending.
- D2-5 Updating BookAvailability from BookAvailabilityChanged is a projection, not a policy: it issues no command and changes no aggregate. It is listed under Queries and read models. Consumption is deduplicated by event id (profile outbox; inbox record per consumer). Proposed.
- D2-6 A Book with no BookAvailabilityChanged received yet shows 0 of 0 available and no due date. Why: Lending has no copies for a book it has not yet heard of (BookAdded -> Lending). Proposed.
- D2-7 AddBook publishes BookAdded with exactly the payload the context map names: book id, title, author (01 context map). The event is written to the Catalog outbox in the same transaction as the Book insert (profile events_messaging).
- D2-8 SearchCatalog and GetBookDetails are open to any Visitor, signed in or not (REQ-1, REQ-3, REQ-29 "the catalog is open to any visitor"). The brief lists REQ-4 under Member; see CQ-4. Proposed.
- D2-9 Book removal and editing are out of scope, following Q-9 in 01. Book therefore has no state machine: it exists from AddBook onward. Proposed.
- D2-10 BookAvailability applies BookAvailabilityChanged only when its `version` is higher than the stored `source_version`; the version strictly increases per book. Source: 03 D3-9 (closes CQ-6).
- D2-11 The Librarian check for AddBook is the synchronous in-process query ResolveCurrentMember, called by the API guard before the command runs; NotLibrarian is returned when the role is not Librarian. Source: 01 context map row Membership -> Catalog (open host service), added under Fixed F1 (closes CQ-7).
- Fixed F11: CQ-6 removed from Open questions; resolved by 03 D3-9 and recorded as D2-10.
- Fixed F1: CQ-7 removed from Open questions; the role check now follows the 01 Membership -> Catalog row, recorded as D2-11.

## Open questions
| Id | Question | Why it matters | Proposed default |
|---|---|---|---|
| CQ-1 | Is ISBN unique across books (brief Q-10)? | Decides the unique constraint in D2-3 and the AddBook failure DuplicateIsbn. | Yes, unique on the normalised ISBN. |
| CQ-2 | Which ISBN forms are accepted, and is the checksum validated? | AddBook failure InvalidIsbn; REQ-24 only says "ISBN". | Accept ISBN-10 and ISBN-13 with or without hyphens, validate the checksum, store as ISBN-13 digits. |
| CQ-3 | How does search match (REQ-1): substring, word, case and accent sensitivity, empty query? | SearchCatalog behaviour and indexes in phase 3. | Case-insensitive substring match on title or author; empty query lists all books; paginated, ordered by title then id. |
| CQ-4 | REQ-4 names Member as actor, REQ-3 and REQ-29 say any visitor opens details. May a Visitor see the book detail? | Authorisation of GetBookDetails. | Yes; only Borrow and Place hold need sign-in (Lending). |
| CQ-5 | When does the detail page show a due date (REQ-4 "when on loan")? | GetBookDetails output. | Show the earliest due date from BookAvailability whenever availableCount is 0 and a due date exists. |
| CQ-8 | Length limits for title and author, and is author one name or a list? | Validation and columns. | Title and author each 1 to 500 characters after trimming; author is one free-text string. |
| CQ-9 | May two books share the same title and author (different editions)? | Duplicate detection beyond ISBN. | Yes; only ISBN is checked. |

## Aggregates
| Aggregate | Root entity | Contains (entities, value objects) | References by id | Invariants (REQ) | Created by |
|---|---|---|---|---|---|
| Book | Book | BookTitle, AuthorName, Isbn | none | A book has a non-empty title, author and ISBN (REQ-24). The ISBN is well formed (REQ-24; form is CQ-2). No two books share an ISBN, enforced by a unique constraint in the AddBook transaction (D2-3; uniqueness is CQ-1). ## Queries and read models
| Query / read model | Kind (query / read model / cache) | Source | Rebuild or invalidation | Staleness | REQ |
|---|---|---|---|---|---|
| SearchCatalog | query | Book table joined with BookAvailability | Not stored; reads current rows. Filter by title or author (CQ-3), paginated; returns bookId, title, author, availableCount, totalCount. | Book data current; counts as stale as BookAvailability. | REQ-1, REQ-2, REQ-3 |
| GetBookDetails | query | Book table joined with BookAvailability, by bookId | Not stored; reads current rows. Returns title, author, ISBN, availableCount, totalCount, earliestDueDate (CQ-5). Fails BookNotFound for an unknown id. | Book data current; counts and due date as stale as BookAvailability. | REQ-3, REQ-4 |
| BookAvailability | read model | Lending integration event BookAvailabilityChanged (per book: available count, total count, earliest due date) | Upsert one row per bookId on each event, deduplicated by eventId, applied only when version exceeds source_version (D2-10). Rebuilt by truncating it and running the Lending maintenance job RepublishBookAvailability, which writes one BookAvailabilityChanged per book at its current version (03-db-design-lending.md D3-L6, F8). Missing row reads as 0 of 0 (D2-6). Never the source of truth (D1-3). | Seconds: the outbox worker lag (profile events_messaging; same assumption as SQ-1). | REQ-2, REQ-4 |
